# Further Qwen3.8 optimization on P150x2

Research date: 2026-09-04. Local source: `51e07b8079b1b91e7c64fbf15c692d0df98fcc35`.

## Result

The best next steps are **MTP lifecycle repair**, **compact token selection**, and **faster prefill**. Larger batches need better prefill and request scheduling, not a wider default alone.

Eight new Cairn changes record the work. The existing MTP change now records current defects and exact acceptance requirements. No runtime code, package pin, service, device state, or production admission changed during this research.

These are research results, not new speed measurements. The analysis uses one assistant, so the review passes are correlated.

## Finding 1: MTP needs lifecycle repair before another optimization claim

The existing change is `.cairn/changes/qwen38-mtp-speculative-serving/`. A new parallel MTP implementation is unnecessary.

### Verified source defects

| Defect | Source | Smallest discriminating check |
| --- | --- | --- |
| Undefined `started` at the result return | `mtp_drafter_adapter.py:832` | `ruff check --select F821` reports the error |
| Economic loss streak never advances from zero | `run_speculative_completion` and `round_economics_disengaged` | Two losing rounds with initial streak zero must disengage |
| Feedback prefix zero remains the initial prompt feedback | `_FeedbackRecorder.__init__`, `record_prefix_feedback`, and later rejection selection | Accept one round, then reject the first draft of the next round |
| Claimed worst-case pool bound assumes more than one emitted token | `planned_rounds` in `run_speculative_completion` | Repeated zero-acceptance rounds must remain within a correct bound |
| Draft input allocation starts after persistent verifier capture | `TracedMtpDraftAdapter.run` calls `_allocate_inputs` lazily | Allocation ledger must cover every trace and scratch buffer |
| Plain fallback starts before persistent traces close | Tail loop before `finally` in `run_speculative_completion` | Inspect allocations and state at speculative-to-plain transition |
| MTP bypasses the batch worker and `_eager_lock` | `server.py:556–625` | Concurrent greedy MTP and sampled requests must share one device owner |
| Timeout is an exception, not enforced process termination | `run_with_watchdog`, HTTP error handler, and cleanup | A stalled fake device worker must not permit cleanup or a second request |

The pool problem causes premature fallback, not a proven buffer overrun. For a 64-token request and draft count 3, the current pool contains 23 entries. Zero acceptance can require 60 speculative rounds before the plain tail.

The loss-counter defect follows directly from the caller. The predicate returns false on the first loss because it requires two losses. The caller then resets the streak to zero.

The round timer ends before rollback. Its fixed per-token budget also does not use the stated live calibration. Therefore, current economic decisions do not measure complete emitted-token cost.

The source already contains a feedback pool. Repeating the old instruction to add a pool misses the remaining allocations and state transitions.

### Correct contract

A round verifies `[seed, draft_0, ..., draft_(k-1)]` and produces `k+1` continuation rows. Acceptance count `j` commits the first `j` drafts and continuation row `j`.

The target state must correspond to the consumed seed plus accepted drafts. The bonus token becomes the next seed. The draft feedback must correspond to that same prefix.

One preallocated, reusable feedback bank is preferable to a bank per possible round. Its reuse requires completion fencing and a refreshed prefix-zero entry. This is a design candidate, not a verified device path.

The allocator source contradicts a blanket claim that every allocation with a resident trace is forbidden. `AllocatorImpl::verify_safe_allocation` warns about unsafe lifetimes. The source permits a temporary allocation whose lifetime ends before replay. Persistent cross-trace buffers still need an explicit non-overlap proof.

A watchdog cannot safely turn an abandoned device call into normal fallback. The shell must quarantine the engine and end the process without concurrent device cleanup. Reset authority remains separate.

## Finding 2: remove full-logit work from token selection

`NativeMtpVerifierAdapter.replay_round` reads a complete vocabulary replica and applies host `argmax` for each row. `_forward_device` calls the gathered `_lm_head` path.

For verifier width 4, the host float32 logits occupy `4 × 248320 × 4 = 3973120` bytes. A value-plus-global-ID winner per row and chip needs 64 logical bytes. These are representation sizes, not measured PCIe transfer sizes or a predicted speedup.

The existing greedy decode tail already provides a shard-local reduction pattern. The verifier can retain the same mathematical result without a vocabulary-wide gather and host conversion.

Sampled serving needs a separate candidate. Its retained 12.91 versus 16.91 tokens/s result motivates measurement of reduction, readback, and host sampling separately.

For global top-K, each shard only needs its local top-K. A candidate absent from local top-K cannot enter global top-K. Stable tie-breaking must use the global token ID.

At TP2, 124160 logits per shard exceed the historical 65536 index boundary in the certified sampler. A bounded sub-shard reduction can keep local indices within that limit. Global offsets must use a wide integer type.

This is exact only for the declared top-K distribution and supported transforms. Candidate-only nucleus sampling does not establish full-vocabulary top-p equivalence. Penalties require a candidate-coverage proof or a safe fallback. The existing greedy first prefill token is part of the current sampled-route behavior.

## Finding 3: evaluate a named runtime, not “latest”

The release API reported `v0.77.0`, published August 18. Its annotated tag resolves to:

`9f9cd4fd590f4b606bd0981a4fe0b6403eb38ec9`

This is the research candidate. The previous uplift archive selected no candidate, so this is new evidence rather than a repeated open-ended upgrade.

The pinned 0.77 source exports `ttnn.transformer.chunk_gated_delta_rule`. Its binding supports initial/final state, head-major output, and caller-owned constant tiles. Traced callers must supply those constants before capture.

The local `gdn-seq-fallback.patch` selects the sequential adapter because 0.74 lacks that operation. The local compatibility patch also gates fused SwiGLU AGMM and TP2 prefill reduction fusion.

A candidate closure must pair runtime, models, compiler, drivers, Python dependencies, simulator, and local kernels. A successful symbol lookup does not prove compatible shapes or trace behavior.

Keep 0.74 as the control. Do not update the global runtime merely because 0.77 exists. Promote each removed fallback only after its exact TP2 path passes.

A newer current-main README still names Qwen3.5/3.6, not the local Qwen3.8 adoption. Therefore, a broad upstream model swap can remove local model registration and authority checks.

## Finding 4: grouped prefill exists, but local admission does not

`BatchedTracedDecodeAdapter.prefill_users` calls `prefill_paged_slots`. The device-staging patch still performs per-user model prefill.

The adopted model already contains `prefill_paged_grouped`. It groups GDN and MLP work while full attention remains per-user. Reuse this implementation boundary instead of inventing another complete model forward.

Its group cap contains a TP4 assumption: 12 value heads per chip. TP2 has 24. Under the older sequential kernel's stated 32-head work limit, two users already require 48 head rows. The newer fused path needs a separate worker-grid and L1 bound.

A blanket `group_size=8` is unsafe. The planner must derive eligibility from runtime capability, head geometry, bucket length, and memory footprint.

The known B8 rejection predates the device-staged prefill result. A fresh screen has a valid new mechanism. Faster prefill alone cannot fix B8's separate 0.735 decode-retention failure.

Masked padding is a correctness boundary. The existing full-bucket trace explicitly rejects short prompts. Simply padding tokens advances GDN state beyond the real prefix.

## Finding 5: request scheduling leaves concurrency unused

The current coordinator collects requests with equal `max_tokens`. It runs the entire group before another group can enter. It does not refill a finished slot during decode.

A persistent slot scheduler can support staggered arrivals and unequal lengths. The first candidate must remain bounded to the admitted B4 capacity. B8 needs its own receipt.

The scheduler core owns slot generations, deadlines, admission, completion, and state ownership. TTNN adapters own page-table updates and state copies. The HTTP shell does not own device policy.

The main obstacle is prefill while a decode trace remains resident. The rejected reuse result proves that zero recaptures alone are insufficient. A safe candidate needs bounded prefill work and complete request-wall measurements.

Upstream decode bucketing is useful reference code, but it already exists in the adopted tree. It does not by itself provide continuous scheduling in the custom service.

## Finding 6: prefix reuse must cache the whole hybrid state

A KV-only prefix cache is incomplete for this model. Reuse requires GDN recurrent state, convolution state, full-attention KV, positions, and any required final hidden row.

A raw recurrent snapshot requires at least:

`48 layers × 24 local value heads × 128 × 128 × 4 bytes = 72 MiB per chip per prefix`.

This excludes convolution state, duplicate buffers, padding, allocator overhead, and MTP state. Dense BF16 KV adds 32768 bytes per token per chip. A 2048-token prefix therefore adds 64 MiB per chip before overhead.

This makes a bounded shared system-prefix cache plausible, but an unbounded cache per conversation expensive. Prefill avoided must exceed lookup, restore, copy-on-write, and eviction costs.

The key must bind exact token IDs, tenant scope, model content, tokenizer/template identity, execution identity, precision, and prefix length. A cache hit does not authorize cross-tenant sharing.

## Finding 7: selective precision is better than blanket BF4

The current defaults already use BF4 MLP gate/up weights. Recommending that change again has no value.

The next low-precision screen targets MLP down projections before sensitive GDN and head paths. The down matrices contain `64 × 17408 × 5120 = 5704253440` elements across the mesh.

A standard block-float tile includes shared exponent bytes. Thus BF4 does not mean exactly half the BFP8 storage. The candidate must measure actual cache and device allocation sizes.

The historical component split places MLP and GDN near one another, not one dominant bandwidth bottleneck. Each component includes layout and collective costs. Halving one weight family cannot halve the full decode step.

Keep recurrent state in FP32. Keep the restored MTP head in BF16. Compare prefill scores, teacher-forced decode logits, chunk-boundary state, and downstream task quality separately.

BF8 KV is a context-dependent bandwidth candidate. At the current 2048-token bound, its priority is lower than prefill and selection work. Long-context benefits from the MoE reference cannot transfer to this dense TP2 deployment.

## Finding 8: tune the actual TP2 shapes and collectives

The package already uses explicit 1D decode grids, not generic AUTO matmul. It also includes fused decay-exp, folded GDN QKVZAB, native full-chunk convolution, and direct fill-width warmup.

The earlier DRAM-sharded projection candidate lost to that tuned baseline. Further tuning must change a measured mechanism, such as TP2 tile utilization or collective startup cost.

A key naming trap exists in `models/tt_transformers/tt/ccl.py`: `tt_all_reduce` returns reduce-scatter on a line mesh. Its name does not establish an all-reduce plus all-gather.

The layer assembly has one attention output reduction and one MLP output reduction per layer. That gives 128 semantic reduction sites per token across 64 layers. Norm, input gather, and head operations add other sites. This is source accounting, not a measured kernel-launch count.

GDN has eight local key heads and 24 local value heads at TP2. Its output projection has local input width 3072. MLP gate/up output width is 8704 per chip. These differ from the TP4 shapes that motivated several upstream grids.

A single FP32 hidden row contains 20 KiB before tile padding. Small-message collective startup can matter more than nominal fabric bandwidth. Measure payload padding and barriers before changing link counts.

The 0.77 release lists a small-shape direct reduce-scatter and newer fused CCL-matmul work. These are candidate leads only. Their exact API, mesh support, and local benefit remain unverified.

## Rejected or deferred directions

- **Enable BF4 everywhere:** conflicts with the MTP acceptance loss and recorded chunk-invariant failures.
- **Enable B8 by lowering thresholds:** changes the acceptance contract without improving the runtime.
- **Keep every trace resident:** repeats the rejected TTFT result and exposes unsafe buffer lifetimes.
- **Add another eager-to-traced project:** traced decode already exists.
- **Add fused exp or wide 1D grids:** the adopted source already contains them.
- **Use Adartras MoE throughput as the dense target:** different layers, weights, mesh, and runtime.
- **Use ordinary KV rollback for GDN:** KV writes do not undo recurrent state.
- **Split prefill and decode across the two cards:** sacrifices the current TP2 weight layout and adds state transfer. No fitting, faster candidate exists.
- **Replace TP2 with two replicas:** fitting a complete model and runtime on each card needs a separate precision and capacity proof.
- **Replace MTP with an external draft model:** checkpoint, training, memory, and local acceptance evidence are missing.
- **Claim top-K sampling equals unrestricted top-p:** omitted probability mass invalidates that claim.

## Measurement and safety contract

The common workload records prompt length, generated length, concurrent arrivals, route, precision, context, and cache state. Cold startup, trace capture, warm decode, and client-visible latency remain separate.

The initial screen stays within the existing context bound. Named profile values cover short prompts, near-boundary prompts, single requests, B4, and any explicit B8 candidate. Existing B4/B8 thresholds remain unchanged.

Each performance control uses matched artifacts and balanced route order. It preserves failed roots, reports duplicate stability, and excludes diagnostic instrumentation from admission timing.

MTP reports total emitted tokens divided by total complete round time. This includes draft, input update, verification, selection, state commit, rollback, and synchronization. Request-wall timing also includes capture and prefill.

The simulator first runs a representative operation and recurrent-state carry. A trace-specific simulator gap must produce an explicit blocker. A simulated result never establishes silicon speed or physical placement.

Hardware runs require an authorized outage, exact device ownership, bounded timeouts, a private diagnostic listener, and a verified recovery path. A watchdog timeout must stop admission and must not race cleanup against a live device thread.

## Research validation and limits

The source review found an existing `F821` error through Ruff. The current Cairn binary and policy also rejected the old MTP package structure before edits. The research repairs only its document structure and records unimplemented work.

No device probe, simulator run, full runtime test, or package upgrade occurred. The final validation record is [validation.md](qwen38-p150x2-2026-09-04/validation.md).

The search used three passes: local evidence, upstream comparison, and adversarial review. The external retrieval budget was 24 targeted calls. The work used 14 GitHub calls and three web fetches. Two GitHub search calls failed authentication. Direct repository endpoints supplied the required source facts.

The terminal result is **validated research with open implementation work**. Stop further retrieval because every retained mechanism has a concrete source, owner, boundary, and next experiment.
