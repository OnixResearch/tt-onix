# LFM3-1.7B bring-up receipts (2026-10-27)

Host: local P150x2 workstation, card 0 (PCIe device 0), TT-Metal 0.77.0, fast
dispatch. Checkpoint `LiquidAI/LFM3-1.7B` under `~/.cache/lfm3`
(`config.json`, `model.safetensors`, `tokenizer.json`). Oracle: the packaged
`pkgs/lfm3/oracle/reference.py` in a virtualenv with transformers 5.12.1 on the
host CPU, float32.

## Package

```
$ nix build .#lfm3 --no-link --option builders ""
# install check imports ttnn against the packaged site-packages; PASS
```

The device entry points serve a writable `TT_METAL_HOME` from
`${XDG_CACHE_HOME:-~/.cache}/lfm3/tt-metal-runtime` (symlink tree of the
packaged overlay). The first run compiles the kernels for these shapes
(about 20 s of prefill); later runs do not reuse them from disk.

## Matmul fidelity probe

`ttnn.linear` on the device against the exact product of the same inputs
(M = 32, K = N = 2048; float32 reference for the fp32 rows, float32-accumulated
bf16 products for the bf16 rows):

| inputs / config | max abs | mean abs |
| --- | --- | --- |
| fp32, default (`HiFi4`, fp32 dest) | 4.8e-3 | 8.4e-4 |
| fp32, `HiFi3` + `fp32_dest_acc_en` | 5.3e-3 | 9.2e-4 |
| fp32, `HiFi2` + `fp32_dest_acc_en` | 2.9e-2 | 5.2e-3 |
| fp32, `LoFi` | 1.2e-1 | 1.7e-2 |
| bf16, default | 6.8e-2 | 6.5e-3 |
| bf16, `HiFi4` + `fp32_dest_acc_en` | 8.3e-3 | 1.1e-3 |

Split-bf16 emulation of a float32 product did not help (max 1.3e-2): the kernel
rounds products, so the extra passes do not recover the wide product. A CPU
float32 reference that dequantizes bf16 weights reaches ~1e-4, which is why the
device stays a few times further from the oracle than an HF bf16 run.

## Non-claims

- No checkpoint pin: the derivation does not fetch or hash the weights.
- No service, supervisor, sampler, stop policy, or streaming endpoint.
- Single device only (`device_id=0`); the second card was not used.
- No traced decode and no batching; the per-token cost is Python dispatch bound.
- No claim about tokens beyond the measured prompts, and none about the bfloat16
  mode as an accuracy gate.
